# SafeNest mmWave — MR60 호환 모델 개발 로드맵

- 작성일: 2026-08-17
- 문서 상태: **ACTIVE_MMWAVE_FUTURE_ROADMAP**
- 대상: 프로젝트 리드, mmWave 담당, 모델 개발, 통합 엔지니어
- 범위: mmWave만. CO₂ / Thermal / Pi 런타임 재설계는 다루지 않는다.
- 성격: 실행 순서 문서. 이 문서를 쓰는 동안 데이터 처리, 학습, 수집, 모델 수정은 하지 않는다.

한 줄로 말하면:

```text
공개 110명 데이터의 사람 다양성 + 라벨
+
팀이 이미 찍어 둔 MR60 센서 domain
↓
둘을 잇는 새로운 호흡 표현을 찾는다
↓
새 모델을 학습한다
↓
기존 MR60 실측으로 먼저 device check
↓
나중에 센서 접근이 될 때 새 사람 데이터로 최종 검증
```

지금 허가된 다음 실행 단계는 **하나뿐이다.**

```text
M-N0 — 기존 팀 MR60 실측 전수조사
```

전처리, 학습, 신규 수집, INT8, Pi 통합은 아직 시작하지 않는다.

---

## 1. 왜 새 로드맵이 필요한가

기존 Phase B 모델은 공개 radar 데이터에서 복원한 **unwrap 위상(라디안)** 을 보고 학습됐다. 실제 SafeNest 런타임이 받는 값은 MR60BHA2 UART `0x0A13`의 vendor `breath_phase`다. 둘은 같은 숫자처럼 보여도 같은 신호가 아니다.

현재 권위 있는 판단은 다음과 같다.

```text
EXISTING_MMWAVE_B_LIVE_GATE = CLOSED
이유 = SIGNAL_CONTRACT_MISMATCH
```

이것은 Pi, ESP32, logger, TFLite 런타임이 깨졌다는 뜻이 아니다. **학습 입력과 실기기 입력의 신호 계약이 다르다**는 뜻이다.

그래서 앞으로는 기존 B 모델을 곱셈, 정규화, 보간, 이득 보정으로 살리지 않는다. 그렇다고 공개 110명 데이터를 버리고 새 MR60만 기다리지도 않는다. 공개 데이터는 사람 다양성과 지도학습 라벨이 있고, 팀 MR60 실측은 우리 센서 domain이 있다. 둘을 잇는 **새 입력 표현**을 만든 뒤 새 모델을 개발한다.

## 3. 무엇을 보존하고, 무엇을 멈추는가

### 보존 — 역사는 유효하다

- 완료된 Phase A (`M-A0`–`M-A6`)와 Phase B (`M-B0`–`M-B12`) 산출물
- 선택된 역사적 후보 `M-B3_CONV1D_GAP_BASELINE_seed42_M-B5_CAL_CLASS_BALANCED_120`
- INT8 SHA-256 `6dff6aaa72c79d76715d40cf7e32bb1e6cd9b2c2e3ac78eaf2fda737561430c5`
- 공개 110명 Zenodo 계보, subject-wise split 지식, A4 proxy 라벨 계약
- 팀이 이미 남긴 물리 MR60 JSONL/CSV와 실패 세션

기존 B 모델은 **VALID historical/offline artifact** 다. 지우거나 이름을 바꾸거나 전처리 계약을 고쳐 live에 맞추지 않는다.

### 정지 — 미래 실행 방향만 교체한다

이전 mmWave 미래 순서는 대략 이랬다.

```text
frozen B 후보
→ M-C0 대응 확인
→ M-C1 신규 실측
→ M-C2 frozen B의 정식 device 평가
→ 측정된 gap이 있을 때만 M-D
```

이 **미래 C/D 실행 방향**은 이제:

```text
PAUSED / SUPERSEDED FOR FUTURE EXECUTION
```

이유: M-C0/M-C2는 “기존 B 입력과 live `breath_phase`가 대응 가능한가”를 전제로 한다. 그 전제가 닫혔다. 완료된 A/B 연대기는 다시 쓰지 않는다. 이전 실행 순서 문서는 역사·세부 근거로 남긴다.

- [기존 mmWave A–E 실행 순서](20260806_ChatGPT_SafeNest_mmWave_Execution_Sequence_01.md) — A/B 역사는 유효, 미래 C/D는 이 문서에 양보
- [멀티센서 master roadmap](20260810_ChatGPT_SafeNest_Multisensor_Parallel_Execution_Roadmap_01.md) — CO₂/Thermal/통합은 유지, mmWave 미래 모델 경로는 이 문서

### 단계 이름

완료된 `M-A` / `M-B` 번호를 바꾸지 않는다. 이전 `M-C` / `M-D`도 역사적 이름으로 남긴다.

새 미래 단계는 **`M-N0`–`M-N12`** 다. `M-`는 mmWave 트랙, `N`은 2026-08-17 이후의 새 모델 계보다. 이전 M-C0 “frozen B 대응 감사”와 새 M-N0 “실측 전수조사”를 같은 일로 부르지 않는다.

새 모델 이름은 기존 B 후보명과 겹치지 않게 한다. 개념적으로 `MR60_COMPAT_...` 또는 저장소 관례에 맞는 새 identity를 쓴다.

## 4. 새 전략이 아닌 것 / 인 것

### 하지 않는다

```text
공개 데이터 폐기 → 센서 올 때까지 대기 → MR60만으로 학습
기존 B에 ×계수 / min-max / 창별 z-score / 조용한 보간
공개 unwrap 위상 + MR60 breath_phase 를 원시값으로 이어 붙여 한 텐서 만들기
vendor breath_rate_raw 로 같은 센서의 정답을 만들어 학습
```

### 한다

```text
공개 110명 데이터     = 큰 지도학습 자원
기존 팀 MR60 실측     = device-domain 증거, 방어 가능할 때만 학습/적응 데이터
최근 Pi 런타임 실측   = 입력/타이밍/분포 참조. 라벨 근거가 확인되기 전에는 지도학습 아님
↓
공통 호흡 표현
↓
새 모델
```

핵심 기술 문제는 이것이다.

> 공개 radar 도메인과 실제 MR60 `breath_phase` 도메인 모두에서 호흡 정보가 의미 있게 남는 **새 표현**을 정의하는 것.

이것은 새 입력 계약이다. 옛 B 계약을 고치는 작업이 아니다.

## 6. M-N0 — 기존 팀 MR60 실측 전수조사

**왜 하는가.**
지금 가진 물리 데이터를 모르면, 학습에 넣을지 / 적응에만 쓸지 / 실패 증거인지를 정할 수 없다. 모델부터 만들면 또 입력 계약이 어긋난다.

**실제로 무엇을 하는가.**
팀 저장소와 이미 이관·인용된 보고서를 기준으로, 알려진 물리 측정 묶음을 찾아 한 장으로 정리한다. 원본 JSONL과 파생 CSV/리포트를 구분한다. 이 단계는 학습하지 않고, 기존 B에 넣어도 되는지 다시 증명하려고 전체 forensic을 반복하지도 않는다.

2026-08-14 평가가 **출발 가설**로 가리키는 예는 아래와 같다. 목록이 완전하다고 가정하지 않는다. M-N0가 live-verify 한다.

| 알려진 후보 | 대략적 조건 | M-N0에서 확인할 것 |
|---|---|---|
| `S001_NORMAL_D06` / `D09` | 재실, 거리 조건 | 원본 경로, 신선도 메타, 사용 가능 역할 |
| `S001_NORMAL_D12` | presence drop 가능성 | 실패/QA로 둘지 |
| `S001_NORMAL_D15` | freeze / lock-loss | 실패/QA로 둘지 |
| paced 12 / 15 / 20 rpm | 지시 호흡, 실패·shallow·deep 포함 | cue ≠ 생리 정답 |
| ~31분 D09 JSONL | 장시간, stale phase 증거 | 타이밍/QA |
| PR18 Pilot Desk-work / Stationary | 캡처 도구 다른 세션 | 레거시와 합치지 말 것 |
| 2026-08-17 Pi JSONL (`data/mmwave/20260817_08_mmwave.jsonl` 등) | 런타임 입력 참조 | 라벨 없으면 지도학습으로 올리지 말 것 |
| 그 외 미요약 물리 측정 | 미상 | 찾아서 빠짐없이 적기 |

세션마다 대략 이 칸이면 충분하다.

| 칸 | 뜻 |
|---|---|
| Session / bundle ID | 세션 정체 |
| Repository path | 원본 위치 |
| Subject | 알면 `S001` 등 |
| Condition | 재실 / paced / 정지 / 실패 등 |
| Duration | 대략 |
| Signal available | `breath_phase` / 기타 |
| Freshness evidence | `phase_age_ms` / 직접 identity / 없음 |
| Reference | 독립 참조 / paced cue / 없음 |
| Label confidence | high / medium / weak / unavailable |
| Known issue | freeze / presence loss / 저진폭 등 |
| Recommended use | 학습 / 적응 / device 참조 / QA / 제외 |

**무엇이 나오면 끝나는가.**
canonical 인벤토리 하나와 짧은 한글 해석. 거대한 증거 DB는 만들지 않는다.

**다음으로 못 가는 경우.**
원본과 파생을 구분하지 못했거나, 빠진 물리 묶음이 남아 “없다”고 단정한 경우. 이 단계에서 Accuracy를 내거나 학습을 시작하면 실패다.

최근 Pi 세션의 초기 분류는 **`RUNTIME_INPUT_REFERENCE`** 다. 숫자 범위, 타이밍, 분포, 파이프 확인용이다. 신뢰할 라벨 근거가 나중에 나오면 재분류할 수 있다. 지금은 지도학습·정식 검증 증거로 올리지 않는다.

## 7. M-N1 — 학습 가능 여부와 라벨 감사

**왜 하는가.**
파일이 있다고 정답이 있는 것은 아니다. 잘못된 라벨로 학습하면 공개 데이터 이득을 센서 환각으로 덮는다.

**실제로 무엇을 하는가.**
M-N0 세션을 아래 중 하나로만 분류한다. 모든 세션을 지도학습에 억지로 넣지 않는다.

```text
SUPERVISED_TRAINING_ELIGIBLE
WEAKLY_LABELED_OR_ADAPTATION_CANDIDATE
DEVICE_DOMAIN_REFERENCE
FAILURE_OR_QA_EVIDENCE
RUNTIME_INPUT_REFERENCE
NO_MODEL_CLAIM
```

특히 지키면 안 되는 것:

```text
paced cue ≠ 실제 생리
MR60 vendor breath_rate_raw ≠ 독립 정답
같은 MR60 호흡수로 같은 MR60 모델을 채점·학습
```

paced 세션은 버릴 필요가 없다. 위상에서 주기가 보이면 약한 조건 메타로 쓸 수 있다. 다만 자신감을 정직하게 적는다. APNEA는 독립 참조가 없으면 임상 주장이 아니라 proxy/비임상이다.

**무엇이 나오면 끝나는가.**
세션별 용도 표. 이후 N3에서 학습 전략 A/B/C를 고르는 근거가 된다.

**다음으로 못 가는 경우.**
순환 라벨을 만들었거나, 실패 세션을 정상 학습 예제로 승격한 경우.

가능한 학습 전략은 N1 이후에 고른다. 지금 미리 하나를 고정하지 않는다.

| 전략 | 공개 110명 | 팀 MR60 |
|---|---|---|
| A | 지도학습 | 방어 가능한 세션만 추가 학습/적응 |
| B | 지도학습 | domain 선택 + 검증만 |
| C | 사전학습 | 적합한 세션만 fine-tune |

## 8. M-N2 — 공개 데이터와 MR60의 공통 표현

**왜 하는가.**
원시 위상 단위가 다르다. 그래도 호흡의 **시간 모양**은 양쪽에서 남을 수 있다. 그 공통 표현이 새 모델의 입력이다.

**실제로 무엇을 하는가.**
후보는 처음에 셋 또는 넷이면 충분하다.

1. **중심화/디트렌드 파형** — 절대 오프셋을 제거하고 시간 모양을 남긴다.
2. **delta / 미분 위상** — 단위보다 변화에 주목한다.
3. **호흡대역 + 스케일-robust 정규화** — 이 정규화는 **새 계약**이다. 옛 `BPF_ZSCORE` 패치가 아니다.
4. **작은 스펙트럼/시간 특징** — 우세 호흡 주파수, 대역 에너지, 자기상관, 규칙성 등. 필요하면 한 묶음으로만.

탐색은 가볍게 한다. 파형, PSD, 자기상관, 분포, 대표 세션 몇 개, paced 비교. 플롯과 짧은 결정 요약으로 충분하다. 이 단계의 모든 통계에 영구 validator를 만들지 않는다. 계약으로 얼릴 것만 나중에 정식화한다.

선택은 한쪽 점수만으로 하지 않는다.

- **공개 도메인:** 지도학습 정보가 남는가.
- **MR60 도메인:** 숫자가 폭발하지 않는가, 호흡 주기가 보이는가, 세션 간 해석이 가능한가, 문서화되지 않은 절대 스케일에 지배되지 않는가, 실제 타이밍을 견디는가.

**무엇이 나오면 끝나는가.**
채택 표현 1개(또는 탈락 이유와 함께 2개까지)와, 왜 공개·MR60 둘 다에서 납득되는지에 대한 짧은 기록.

**다음으로 못 가는 경우.**
원시 두 도메인을 이어 붙였거나, 공개 성능만 보고 고른 경우, 또는 표현이 MR60에서 무의미한 경우.

---

## 9. M-N3 — 새 입력·타이밍·데이터 전략 고정

**왜 하는가.**
표현이 괜찮아 보여도 창, 시각, 라벨, 공개/MR60 사용법이 흔들리면 모델이 또 다른 계약을 갖게 된다.

**실제로 무엇을 하는가.**
다음을 한 번에 얼린다.

```text
새 입력 표현
타이밍 출처
창 정의
리샘플 여부
정규화 전략
라벨 전략
공개 데이터와 MR60을 각각 어떻게 쓰는가
```

옛 B 계약(`10 Hz / 300 / 30 s / BPF_ZSCORE`)은 역사에 남긴다. 자동 상속하지 않는다. 다만 타이밍을 과하게 설계하지도 않는다. 실측을 보고 아래 중 소수만 비교한다.

```text
A. 고정 시간 창 (timestamp 기준)
B. 고정 샘플 수 창
C. 간단한 고정 cadence 리샘플 — 이유가 있을 때만
```

계약문은 세 시각을 구분한다. 또 한 번의 대형 forensic은 하지 않는다.

```text
MR60 소스 phase 갱신
ESP 텔레메트리
Pi 수신
```

**타깃 결정도 여기서 닫는다.** 역사적 3-class를 자동 유지하지 않는다.

| 옵션 | 언제 주력으로 쓰는가 |
|---|---|
| `NORMAL` / `RAPID_OR_ABNORMAL` / `APNEA` proxy | 공개 라벨을 새 표현에 방어 가능하게 옮길 수 있을 때 |
| 호흡수 회귀 | 독립 정답이 분류보다 더 단단할 때 |
| 신호 품질 게이트 | 나쁜 MR60 창을 거르는 보조. 주력 모델을 대체하지 않음 |

권고: **주력 하나 + 보조 품질 게이트 최대 하나.** 모델을 여러 개로 키우지 않는다. APNEA는 계속 비임상 proxy다.

공개 110명의 subject-wise 분할 지식은 보존한다. 새 표현 때문에 창을 다시 만들면 **새 derived track** 으로 만들고, 옛 B LOCKED_TEST 점수를 새 모델 점수로 복사하지 않는다.

**무엇이 나오면 끝나는가.**
새 모델 입력 계약 문서 하나. 역사적 B 계약은 수정하지 않는다.

**다음으로 못 가는 경우.**
사용 전략(A/B/C)이 N1과 모순되거나, 옛 B 전처리를 몰래 재사용한 경우.

---

## 10. M-N4 — 전처리와 창 선택

**왜 하는가.**
N2가 표현 가족을 고르고, N3가 계약을 닫기 직전·직후에 재현 가능한 전처리 한 줄을 정한다.

**실제로 무엇을 하는가.**
큰 ablation을 하지 않는다. 비교는 예를 들어:

- 고른 공통 표현 그대로
- 가벼운 디트렌드
- 단순 호흡대역 필터
- delta
- 필요할 때만 TRAIN-only 전역 정규화

통계는 TRAIN에만 맞춘다. VAL/TEST에 맞추지 않는다.

**무엇이 나오면 끝나는가.**
전처리 한 줄과 창 한 줄, 재현 메타데이터.

**다음으로 못 가는 경우.**
옛 `BPF_ZSCORE`를 “일단 그대로” 가져온 경우, 또는 탐색 격자가 모델 선정보다 커진 경우.

---

## 11. M-N5 — 새 후보 학습

**왜 하는가.**
목표는 복잡한 네트워크가 아니라, 공통 표현이 장치에서도 버틸 만큼 단순한 모델이다.

**실제로 무엇을 하는가.**
초기 후보는 이 정도면 된다.

1. 단순 특징 / 선형 baseline
2. 작은 Conv1D
3. Conv1D + GAP

가벼운 시간 모델을 하나 더 넣는 것은 이유가 있을 때만. 아키텍처 탐색, 대형 transformer/RNN은 하지 않는다.

센서가 없어서 모델 작업을 멈추지 않는다. N0–N9는 기존 공개 데이터와 기존 팀 MR60으로 진행한다. 새 물리 접근은 최종 검증과, 그때 남는 구멍의 적응용이다.

**무엇이 나오면 끝나는가.**
작은 후보군과 TRAIN/VAL 기록. LOCKED_TEST로 고르지 않는다.

**다음으로 못 가는 경우.**
기존 B 가중치를 이어 받아 “새 모델”이라고 부르거나, 무관한 트랙 코드를 섞은 경우.

---

## 12. M-N6 — 오프라인 선정과 새 LOCKED_TEST

**왜 하는가.**
사람 다양성은 공개 데이터에 있다. 장치 적합성은 그다음 N7에서 본다.

**실제로 무엇을 하는가.**
선정은 TRAIN/VALIDATION만. 분류면 Macro F1, 클래스별 recall, confusion. 회귀면 MAE/RMSE와 오차 분포. 모델 크기와 추론 단순함도 적는다. 복잡한 랭킹 프레임워크는 만들지 않는다.

계약이 얼면:

```text
TRAIN / VALIDATION / LOCKED_TEST
```

를 새로 고정한다. 표현, 전처리, 구조, 임계값, class weight를 고르려고 LOCKED_TEST를 반복 열어보지 않는다. 최종 평가는 한 번을 목표로 한다.

**무엇이 나오면 끝나는가.**
선정된 float 후보와, 그 후보만의 locked 평가 기록.

**다음으로 못 가는 경우.**
역사적 B locked-test를 새 점수로 쓴 경우.

---

## 13. M-N7 — 기존 MR60 device-domain 평가

**왜 하는가.**
공개 데이터에서 좋아도, 우리 센서에서 붕괴하면 배포 후보가 아니다. 반대로 기존 실측만으로 최종 일반화를 주장하지도 않는다.

**실제로 무엇을 하는가.**
N1 분류를 그대로 쓴다.

- 신뢰할 라벨이 있는 세션: 방어 가능한 지표만
- 약한 라벨: 일관성/행동 확인
- 무라벨 device 참조: 출력 붕괴, 세션 안정, 분포 이동, 주장 가능한 경향만
- 실패 세션: 불안정해지는지, 거를 수 있는지

무라벨 데이터에 Accuracy/F1을 만들지 않는다.

**무엇이 나오면 끝나는가.**
기존 MR60에 대한 device check 기록. 정식 다피험자 검증이 아님을 명시한다.

**다음으로 못 가는 경우.**
약한 세션을 정식 검증셋으로 승격한 경우.

---

## 14. M-N8 — 구멍이 측정됐을 때만 적응

적응은 기본값이 아니다. N7에서 새 표현/모델이 기존 MR60에서 납득되면 건너뛴다.

구멍이 보이면 그때만, N1에서 해당 방법에 맞는 세션만 써서:

- 혼합 도메인 학습
- MR60 fine-tune
- 재보정
- 제한된 domain adaptation

약한 라벨을 강한 라벨처럼 쓰지 않는다.

---

## 15. M-N9 — FULL_INT8과 Pi 준비

float 후보가 고른 뒤에만 한다.

필수 확인만 한다.

- 변환 성공
- 입출력 텐서 계약
- 보정 예제는 TRAIN 유래
- float 대비 성능 저하가 납득됨
- 심한 saturation 없음
- Pi가 로드/실행 가능

양자화 대감사를 기본으로 두지 않는다. 문제가 생기면 그때 깊게 본다. 변환만으로 배포 준비를 주장하지 않는다.

이 단계가 끝나도 **mmWave live gate는 열지 않는다.** 새 모델이 독립적으로 준비된 뒤에만 통합을 다시 본다. 이 로드맵에서 Pi 런타임·펌웨어를 수정하지 않는다.

## 16. 센서 접근 게이트 — 여기서부터가 신규 실측

N0–N9는 기존 공개 데이터와 기존 팀 MR60으로 한다. 센서가 당장 없다고 모델 작업을 멈추지 않는다.

신규 물리 접근이 필요한 이유:

```text
새 다피험자 데이터
+
독립 참조
+
정식 device-domain 검증
```

그리고 그때 남는 구멍이 있으면 최종 적응.

## 17. M-N10 — 신규 MR60 수집

실측 안내서를 따른다. 큰 실험 행렬을 만들지 않는다. 일반화를 볼 만큼만 찍는다.

짧게 고정할 것:

- 여러 사람
- 선택한 타깃에 맞는 참조 방법
- subject / session ID
- 필요하면 거리·자세
- phase 신선도·타이밍
- 원본 보존

많이 찍는 것이 목적이 아니다.

새 모델이, 학습/튜닝에 쓰지 않은 실제 MR60 측정으로 일반화된다

가능한 한 새 사람, 선택한 타깃에 맞는 독립 참조, 학습에 안 쓴 데이터를 쓴다.

```text
모델이 Pi에서 돌아간다
≠
실제 MR60 domain에서 검증됐다
```

## 20. Lean Validation Policy

대부분의 노력은 여기 쓴다.

```text
실제 데이터
신호 이해
전처리
모델링
device-domain 평가
```

검증 기계를 키우는 데 쓰지 않는다. 검증은 **실제 실패 모드를 막을 때만** 둔다.

### 남기는 것

- 데이터 출처 identity
- subject / session identity
- 라벨 출처
- 누수 방지
- TRAIN-only fitting
- locked-test 규율
- 원본 실측 불변
- 얼린 모델 아티팩트 identity
- 기본 Pi 추론 스모크

### 기본으로 요구하지 않는 것

- 저장소 전체 재감사 반복
- 같은 내용의 보고서 여러 벌
- 중간 통계마다 별도 manifest
- 무관한 센서 테스트
- 문서 문장 단위 테스트
- 실험 단계마다 checksum 재생성
- 임시 실험용 대형 negative suite
- 완료된 A/B 증거를 다시 증명

탐색 질문은 플롯/표로 답하면 된다. **canonical 모델 계약이 되는 것만** 정식화한다.

테스트는 침묵한 구현 오류가 모델을 오염시킬 곳에만 둔다.

- 표현/전처리 구현
- split 누수
- 라벨 매핑
- 텐서 계약
- 최종 데이터셋 결정성
- Pi 추론

문장이 맞는지, 메타데이터 칸마다 테스트하지 않는다.

각 단계는 보통:

```text
질문 하나 → 산출물 하나 → gate 하나
```

작은 결정에 validator·보고서·기계 산출물을 여러 개 요구하지 않는다.

## 21. Git 격리

mmWave 전용 브랜치에서만 작업한다. 단계 시작/끝에 이 정도면 충분하다.

```bash
git fetch origin
git status --short
git log origin/main..HEAD --oneline
git diff origin/main...HEAD --name-only
```

워킹트리가 깨끗해도, `origin/main`에 없는 CO₂ / Thermal / Integration 커밋이 브랜치에 있으면:

```text
PARALLEL_TRACK_BRANCH_CONTAMINATION
```

한 단계 안에서 같은 확인을 반복하지 않는다. 상황이 바뀔 때만 다시 본다.

기존 A6 canonical, 옛 split ID, 옛 라벨, 옛 B 지표, 옛 LOCKED_TEST는 덮어쓰지 않는다. 새 계보는 새 산출물을 만든다.

## 23. 이 로드맵이 성공하려면

다음이 모두 진실이어야 한다.

1. 역사적 A/B와 B 아티팩트가 그대로 남아 있다.
2. 공개 110명이 주요 지도학습 자원으로 쓰인다.
3. 기존 팀 MR60이 버려지지 않고, 용도별로 정직하게 쓰인다.
4. 원시 위상 도메인을 이어 붙이지 않는다.
5. 공통 표현이 새 입력 계약이 된다.
6. 새 모델이 기존 증거로 먼저 만들어지고, 신규 센서 접근은 최종 검증에 쓰인다.
7. 검증은 최소 충분 증거만 남긴다.
